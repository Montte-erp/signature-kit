title: First Use
description: "Load an A1 certificate, inspect the identity, sign bytes, then sign and validate an ITI-ready PDF in one Effect path."
---

**What you'll do:** assemble an Effect program that loads the A1 certificate, reads the identity, signs and verifies bytes — then signs a PDF with the ICP-Brasil AD-RB policy and validates it locally before an optional official ITI submission.

<Steps>
  <Step title="Install">
    Add the core boundary, the A1 signer, the PDF/XML formats, the ITI validator, the shared HTTP client, and `effect` for the `Effect` runtime and `Redacted`.

    ```bash
    bun add @signature-kit/signatures @signature-kit/a1 @signature-kit/pdf @signature-kit/xml @signature-kit/iti @signature-kit/http effect
    ```
  </Step>

  <Step title="Load the A1, inspect, sign and verify">
    `a1SignaturesLayer` takes the `.pfx` bytes and the `Redacted` password and provides the `Signatures` service. Inside one `Effect.gen`, `signatures.inspect()` returns a normalized `SignerIdentity` — `document` carries the e-CPF or e-CNPJ when present — then `signatures.sign` and `signatures.verify` run over the same boundary. `verify` returns a value: `result.valid` is a `boolean`, and a real failure surfaces as a `SignatureKitError` in the error channel, never a thrown exception.

    <Callout type="error" title="The .pfx bytes, not the path">
      `pfx` is a `Uint8Array` holding the binary contents of the `.pfx`/`.p12` — not the file path string. Keep these bytes and the password out of logs and version control.
    </Callout>

    ```ts title="quickstart.node.ts"
    import { readFileSync } from "node:fs"
    import { a1SignaturesLayer } from "@signature-kit/a1/signer"
    import { signatures } from "@signature-kit/signatures"
    import { Effect, Redacted } from "effect"

    const pfx = new Uint8Array(readFileSync("certificates/a1.pfx"))
    const password = Redacted.make(process.env.A1_PASSWORD ?? "")

    const layer = a1SignaturesLayer({ pfx, password })

    export const program = Effect.gen(function* () {
      // normalized identity — identity.document carries e-CPF / e-CNPJ
      const identity = yield* signatures.inspect()

      const content = new TextEncoder().encode("content to sign")
      const artifact = yield* signatures.sign({
        content,
        algorithm: "rsa-sha256",
      })

      const result = yield* signatures.verify({
        content,
        signature: artifact.signature,
        algorithm: artifact.algorithm,
      })

      return { identity, artifact, result }
    }).pipe(Effect.provide(layer))
    ```
  </Step>

  <Step title="Run the program">
    Run the `Effect` with `Effect.runPromise`, or call it from another Effect program.

    ```ts title="run.ts"
    import { Effect } from "effect"

    const { result } = await Effect.runPromise(program)
    console.log(result.valid) // boolean — true if the signature checks out
    ```
  </Step>

  <Step title="Sign XML and PDF">
    Both formats consume the same boundary via `Effect.provide`; the `layer` line is identical to the previous step. XML also needs `xmlRuntimeLayer`; `verifyXml` / `verifyPdf` read the public key from the document and do not require the boundary.

    ```ts title="documents.ts"
    import { signXml } from "@signature-kit/xml/sign"
    import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
    import { signPdf } from "@signature-kit/pdf/sign"
    import { Effect } from "effect"

    const signedXml = signXml({ xml, referenceId: "nfe-1" })
      .pipe(Effect.provide(layer), Effect.provide(xmlRuntimeLayer))

    const signedPdf = signPdf({
      pdf,
      policy: "pades-icp-brasil",
      name: "Maria Souza",
    }).pipe(Effect.provide(layer))
    ```
  </Step>

  <Step title="Validate the signed PDF">
    Close the loop before shipping the file. `validatePdfConformance` checks the AD-RB structure offline; `validatePdfWithIti` optionally submits the same bytes to the official Validar endpoint. Pass `trustedRoots` when you want local chain validation; without roots the certification path is reported as `"not_checked"`.

    ```ts title="validate-pdf.ts"
    import { signatureHttpClientLive } from "@signature-kit/http"
    import { validatePdfConformance } from "@signature-kit/iti/conformance"
    import { validatePdfWithIti } from "@signature-kit/iti/remote"
    import { Effect } from "effect"

    const validation = Effect.gen(function* () {
      const local = yield* validatePdfConformance({
        pdf: signedPdf,
        trustedRoots,
      })

      const remote = yield* validatePdfWithIti({
        source: { pdf: signedPdf },
        fileName: "signed.pdf",
      })

      return { local, remote }
    }).pipe(Effect.provide(signatureHttpClientLive))
    ```
  </Step>
</Steps>

## Errors you might see

<Callout type="warn" title="Incorrect certificate password">
  If the `.pfx` password is wrong, the boundary fails with [`signature-kit.WRONG_PASSWORD`](/docs/signing/errors#err-WRONG_PASSWORD) in the error channel — not an exception. Check the secret before proceeding.
</Callout>

- [`signature-kit.WRONG_PASSWORD`](/docs/signing/errors#err-WRONG_PASSWORD) — incorrect certificate password.
- [`signature-kit.SIGN_FAILED`](/docs/signing/errors#err-SIGN_FAILED) — failed to sign the content.
- [`signature-kit.VERIFY_FAILED`](/docs/signing/errors#err-VERIFY_FAILED) — failed to verify the signature.
