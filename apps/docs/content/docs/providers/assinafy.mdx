**What you'll do:** create a Assinafy remote-signature request, keep credentials Redacted, and use only the lifecycle helpers exported by `@signature-kit/assinafy`.

Assinafy creates a document, registers the signer, and creates the assignment in the configured account. SignatureKit keeps the request shape typed and leaves ceremony ownership to Assinafy.

## Installation

```package-install
@signature-kit/http @signature-kit/assinafy
```

## When to use

Use Assinafy when account-level organization and assignment tracking belong in Assinafy. Use local signing when your app owns the signed bytes and placement.

<Callout type="error" title="Keep credentials Redacted">
  Provider tokens enter as `Redacted.make(...)` and are unwrapped only inside the package HTTP boundary. Never pass remote tokens to React components or logs.
</Callout>

## Minimal request

```ts title="assinafy.ts"
import * as Alchemy from "alchemy"
import { AssinafySignatureRequest, providers as assinafyProviders } from "@signature-kit/assinafy"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Effect, Layer, Redacted } from "effect"

export default class Contracts extends Alchemy.Stack<Contracts>()(
  "Contracts",
  {
    providers: assinafyProviders({
        accountId: process.env.ASSINAFY_ACCOUNT_ID ?? "",
        apiKey: Redacted.make(process.env.ASSINAFY_API_KEY ?? ""),
        environment: "sandbox",
      }).pipe(
        // effect-boundary: Alchemy StackProps.providers closes provider and transport layers. [allow-provide]
        Layer.provide(signatureHttpClientLive),
        Layer.orDie,
      ),
    state: Alchemy.inMemoryState(),
  },
  Effect.gen(function* () {
    return yield* AssinafySignatureRequest("contract", {
      title: "Service agreement",
      message: "Please sign this agreement.",
      documents: [
        { fileName: "contract.pdf", mimeType: "application/pdf", contentBase64: pdfBase64 },
      ],
      recipients: [{ name: "Maria Souza", email: "maria@example.com", routingOrder: 1 }],
      send: false,
    })
  }),
) {}
```

## Lifecycle

| Function | Supported | Notes |
| --- | --- | --- |
| `AssinafySignatureRequest(id, props)` | Yes | Retained Alchemy resource. `reconcile` creates once and returns cached output on later plans. |
| `getAssinafySignatureRequest(options, id)` | Yes | Reads the upstream request state. |
| `listAssinafySignatureRequests(options)` | Yes | Package-level upstream list endpoint; Alchemy provider `list` returns `[]` and `nuke` is skipped. |
| Cancel helper | Not exported | This provider package does not expose a public cancel helper. Use delete only when the upstream supports removing the remote request. |
| `deleteAssinafySignatureRequest(options, id)` | Yes | Deletes the upstream request when the provider supports deletion. A missing remote is success. |
| `downloadAssinafySignedDocument(options, id)` | Yes | Only succeeds after Assinafy exposes a completed download artifact; before that it fails as `signature-kit.UNSUPPORTED_OPERATION`. |

Multi-step create rollback deletes remote state only after unambiguous pre-effect 4xx failures, excluding 408, 409, 429, 5xx, timeouts, and response-shape failures.

## Errors

Invalid input, remote HTTP failures, and invalid response shapes fail as `SignatureKitError`. The `provider`, `operation`, and HTTP `status` fields are preserved when the upstream response exposes them.
