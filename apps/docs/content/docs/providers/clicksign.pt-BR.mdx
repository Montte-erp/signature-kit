---
title: Clicksign
description: "Crie requests de documento Clicksign v1 com credenciais Redacted e erros tipados do SignatureKit."
---

**O que você vai fazer:** criar um request remoto de assinatura Clicksign, manter credenciais Redacted e usar apenas os helpers de lifecycle exportados por `@signature-kit/clicksign`.

Clicksign cria o documento e o signatário no upstream, opcionalmente notifica o destinatário e devolve um registro `ClicksignSignatureRequestAttributes` próprio da Clicksign. Ele não é backend local de `Signatures` e não muta bytes de PDF no processo.

## Instalação

```package-install
@signature-kit/http @signature-kit/clicksign
```

## Quando usar

Use Clicksign quando a cerimônia de assinatura, lembretes e trilha de auditoria vivem na Clicksign. Use assinatura local A1/PDF quando sua app precisa produzir os bytes assinados diretamente.

<Callout type="error" title="Mantenha credenciais Redacted">
  Tokens de provedor entram como `Redacted.make(...)` e são abertos apenas dentro da fronteira HTTP do pacote. Nunca passe tokens remotos para componentes React ou logs.
</Callout>

## Request mínimo

```ts title="clicksign.ts"
import * as Alchemy from "alchemy"
import { ClicksignSignatureRequest, providers as clicksignProviders } from "@signature-kit/clicksign"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Effect, Layer, Redacted } from "effect"

export default class Contracts extends Alchemy.Stack<Contracts>()(
  "Contracts",
  {
    providers: clicksignProviders({
        accessToken: Redacted.make(process.env.CLICKSIGN_ACCESS_TOKEN ?? ""),
        environment: "sandbox",
        autoClose: true,
      }).pipe(
        // effect-boundary: Alchemy StackProps.providers closes provider and transport layers. [allow-provide]
        Layer.provide(signatureHttpClientLive),
        Layer.orDie,
      ),
    state: Alchemy.inMemoryState(),
  },
  Effect.gen(function* () {
    return yield* ClicksignSignatureRequest("contract", {
      title: "Contrato de prestação de serviço",
      message: "Revise e assine este documento.",
      documents: [
        { fileName: "contract.pdf", contentBase64: pdfBase64, mimeType: "application/pdf" },
      ],
      recipients: [{ name: "Maria Souza", email: "maria@example.com", role: "signer" }],
      send: true,
    })
  }),
) {}
```

## Lifecycle

| Função | Suportada | Notas |
| --- | --- | --- |
| `ClicksignSignatureRequest(id, props)` | Sim | Recurso Alchemy retido. `reconcile` cria uma vez e devolve o output em cache nos planos seguintes. |
| `getClicksignSignatureRequest(options, id)` | Sim | Lê o estado do request upstream. |
| `listClicksignSignatureRequests(options)` | Sim | Endpoint upstream de listagem no pacote; o `list` do provider Alchemy devolve `[]` e `nuke` é pulado. |
| `cancelClicksignSignatureRequest(options, id)` | Sim | Usa o endpoint de cancelamento do provedor para requests remotos canceláveis. |
| `deleteClicksignSignatureRequest(options, id)` | Sim | Deleta o request upstream quando o provedor suporta deleção. Remoto ausente é sucesso. |
| `downloadClicksignSignedDocument(options, id)` | Sim | Só funciona quando a Clicksign expõe URL de arquivo assinado no estado concluído. Antes disso falha como `signature-kit.UNSUPPORTED_OPERATION`. |

Rollback de recurso retido é conservador: cleanup de criação multi-etapa só deleta estado remoto depois de falhas 4xx inequívocas antes do efeito externo final. Ele não faz rollback depois de 408, 409, 429, 5xx, timeouts, falhas de shape de resposta ou depois de efeitos de notificação.

## Erros

Input inválido, falhas HTTP remotas e shapes de resposta inválidos falham como `SignatureKitError`. Os campos `provider`, `operation` e `status` HTTP são preservados quando a resposta upstream expõe esses dados.
