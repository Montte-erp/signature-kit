**What you'll do:** create a Clicksign remote-signature request, keep credentials Redacted, and use only the lifecycle helpers exported by `@signature-kit/clicksign`.

Clicksign creates the upstream document and signer, optionally notifies the recipient, then returns a Clicksign-owned `ClicksignSignatureRequestAttributes` record. It is not a local `Signatures` backend and it does not mutate PDF bytes in-process.

## Installation

```package-install
@signature-kit/http @signature-kit/clicksign
```

## When to use

Use Clicksign when the signing ceremony, reminders, and audit trail live in Clicksign. Use local A1/PDF signing when your app must produce signed bytes directly.

<Callout type="error" title="Keep credentials Redacted">
  Provider tokens enter as `Redacted.make(...)` and are unwrapped only inside the package HTTP boundary. Never pass remote tokens to React components or logs.
</Callout>

## Minimal request

```ts title="clicksign.ts"
import * as Alchemy from "alchemy"
import { ClicksignSignatureRequest, providers as clicksignProviders } from "@signature-kit/clicksign"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Effect, Layer, Redacted } from "effect"

export default class Contracts extends Alchemy.Stack<Contracts>()(
  "Contracts",
  {
    providers: clicksignProviders({
        accessToken: Redacted.make(process.env.CLICKSIGN_ACCESS_TOKEN ?? ""),
        environment: "sandbox",
        autoClose: true,
      }).pipe(
        // effect-boundary: Alchemy StackProps.providers closes provider and transport layers. [allow-provide]
        Layer.provide(signatureHttpClientLive),
        Layer.orDie,
      ),
    state: Alchemy.inMemoryState(),
  },
  Effect.gen(function* () {
    return yield* ClicksignSignatureRequest("contract", {
      title: "Service agreement",
      message: "Please review and sign this document.",
      documents: [
        { fileName: "contract.pdf", contentBase64: pdfBase64, mimeType: "application/pdf" },
      ],
      recipients: [{ name: "Maria Souza", email: "maria@example.com", role: "signer" }],
      send: true,
    })
  }),
) {}
```

## Lifecycle

| Function | Supported | Notes |
| --- | --- | --- |
| `ClicksignSignatureRequest(id, props)` | Yes | Retained Alchemy resource. `reconcile` creates once and returns cached output on later plans. |
| `getClicksignSignatureRequest(options, id)` | Yes | Reads the upstream request state. |
| `listClicksignSignatureRequests(options)` | Yes | Package-level upstream list endpoint; Alchemy provider `list` returns `[]` and `nuke` is skipped. |
| `cancelClicksignSignatureRequest(options, id)` | Yes | Uses the provider cancel endpoint for cancellable remote requests. |
| `deleteClicksignSignatureRequest(options, id)` | Yes | Deletes the upstream request when the provider supports deletion. A missing remote is success. |
| `downloadClicksignSignedDocument(options, id)` | Yes | Only succeeds when Clicksign exposes a signed-file URL in the completed state. Before that it fails as `signature-kit.UNSUPPORTED_OPERATION`. |

Retained-resource rollback is conservative: multi-step create cleanup deletes remote state only after unambiguous pre-effect 4xx failures. It does not roll back after 408, 409, 429, 5xx, timeouts, response-shape failures, or after notification side effects.

## Errors

Invalid input, remote HTTP failures, and invalid response shapes fail as `SignatureKitError`. The `provider`, `operation`, and HTTP `status` fields are preserved when the upstream response exposes them.
