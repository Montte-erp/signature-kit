title: Documenso
description: "Crie envelopes Documenso v2 com upload multipart de PDF e erros tipados do SignatureKit."
---

**O que você vai fazer:** criar um request remoto de assinatura Documenso, manter credenciais Redacted e usar apenas os helpers de lifecycle exportados por `@signature-kit/documenso`.

Documenso cria um envelope v2, envia PDFs como arquivos multipart e pode distribuir o envelope quando `send` está ativo.

## Instalação

```package-install
@signature-kit/http @signature-kit/documenso
```

## Quando usar

Use Documenso quando posse do envelope, roteamento e ações do destinatário ficam no Documenso. Use assinatura local para bytes PDF/PAdES no processo.

<Callout type="error" title="Mantenha credenciais Redacted">
  Tokens de provedor entram como `Redacted.make(...)` e são abertos apenas dentro da fronteira HTTP do pacote. Nunca passe tokens remotos para componentes React ou logs.
</Callout>

## Request mínimo

```ts title="documenso.ts"
import * as Alchemy from "alchemy"
import { DocumensoSignatureRequest, providers as documensoProviders } from "@signature-kit/documenso"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Effect, Layer, Redacted } from "effect"

export default class Contracts extends Alchemy.Stack<Contracts>()(
  "Contracts",
  {
    providers: documensoProviders({
        apiKey: Redacted.make(process.env.DOCUMENSO_API_KEY ?? ""),
        authorizationScheme: "bearer",
      }).pipe(
        // effect-boundary: Alchemy StackProps.providers closes provider and transport layers. [allow-provide]
        Layer.provide(signatureHttpClientLive),
        Layer.orDie,
      ),
    state: Alchemy.inMemoryState(),
  },
  Effect.gen(function* () {
    return yield* DocumensoSignatureRequest("contract", {
      title: "Contrato de prestação de serviço",
      message: "Assine este contrato.",
      documents: [
        { fileName: "contract.pdf", mimeType: "application/pdf", contentBase64: pdfBase64 },
      ],
      recipients: [{ name: "Maria Souza", email: "maria@example.com", role: "signer", routingOrder: 1 }],
      send: false,
    })
  }),
) {}
```

## Lifecycle

| Função | Suportada | Notas |
| --- | --- | --- |
| `DocumensoSignatureRequest(id, props)` | Sim | Recurso Alchemy retido. `reconcile` cria uma vez e devolve o output em cache nos planos seguintes. |
| `getDocumensoSignatureRequest(options, id)` | Sim | Lê o estado do request upstream. |
| `listDocumensoSignatureRequests(options)` | Sim | Endpoint upstream de listagem no pacote; o `list` do provider Alchemy devolve `[]` e `nuke` é pulado. |
| `cancelDocumensoSignatureRequest(options, id)` | Sim | Usa o endpoint de cancelamento do provedor para requests remotos canceláveis. |
| `deleteDocumensoSignatureRequest(options, id)` | Sim | Deleta o request upstream quando o provedor suporta deleção. Remoto ausente é sucesso. |
| `downloadDocumensoSignedDocument(options, id)` | Sim | Só funciona depois que o envelope está concluído e um item de envelope está disponível; caso contrário falha como `signature-kit.UNSUPPORTED_OPERATION`. |

Rollback de criação multi-etapa só deleta estado remoto depois de falhas 4xx inequívocas antes do efeito externo final, excluindo 408, 409, 429, 5xx, timeouts e falhas de shape de resposta.

## Erros

Input inválido, falhas HTTP remotas e shapes de resposta inválidos falham como `SignatureKitError`. Os campos `provider`, `operation` e `status` HTTP são preservados quando a resposta upstream expõe esses dados.
