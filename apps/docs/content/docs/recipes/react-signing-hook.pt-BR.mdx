title: Hook de assinatura React
description: "Use hooks de @signature-kit/react para carregar certificado, assinar PDFs em sequência, renderizar progresso e manter erros tipados brutos."
---

`@signature-kit/react` é a fronteira da aplicação para assinatura A1 no navegador. Ele continua headless: sem storage, sem fetch/tRPC, sem toasts, sem modais, sem `react-pdf` e sem componentes UI publicados no npm.

Caminho rápido: instale a UI de registry na sua app e edite os arquivos gerados.

```bash title="Instale o dialog de assinatura direta"
npx shadcn@latest add https://signaturekit.dev/r/signature-dialog.json
```

Precisa de UI própria? Use os hooks diretamente.

## Estado do certificado

```tsx title="certificate-form.tsx"
import { useA1Certificate } from "@signature-kit/react/a1"

export function CertificateForm() {
  const certificate = useA1Certificate()

  return (
    <form
      onSubmit={async (event) => {
        event.preventDefault()
        const form = new FormData(event.currentTarget)
        const file = form.get("certificate")
        const password = form.get("password")
        if (!(file instanceof File) || typeof password !== "string") return
        await certificate.load(file, password)
      }}
    >
      <input name="certificate" type="file" accept=".pfx,.p12" />
      <input name="password" type="password" />
      <button type="submit">Carregar certificado</button>
    </form>
  )
}
```

`certificate.state` carrega o erro tipado bruto quando o carregamento falha. Mantenha esse valor bruto até a hora de renderizar.

## Assinatura PDF sequencial

```tsx title="sign-documents.tsx"
import { usePdfSignatureQueue } from "@signature-kit/react/browser-pdf"

export function SignDocuments({ items }: { items: readonly PdfSignatureQueueItem[] }) {
  const queue = usePdfSignatureQueue()

  return (
    <button
      disabled={queue.snapshot.busy}
      onClick={() => queue.sign(items)}
    >
      Assinar documentos
    </button>
  )
}
```

As linhas atualizam em ordem: `pending -> signing -> signed | failed`. A assinatura roda com concorrência 1, e falhas por linha preservam o erro tipado bruto (`PdfError`, `CmsError` ou `SignatureKitError`) para a app chamar `errorMessage(...)` de `@signature-kit/i18n` com a locale e os catálogos corretos.

## Erros localizados por linha

```tsx title="row-error.tsx"
import { cmsErrorMessages } from "@signature-kit/cms/config"
import { errorMessage } from "@signature-kit/i18n"
import { pdfErrorMessages } from "@signature-kit/pdf/config"
import { signatureKitErrorMessages } from "@signature-kit/signatures"

const label = errorMessage(row.error, {
  locale: "pt-BR",
  catalogs: [signatureKitErrorMessages, pdfErrorMessages, cmsErrorMessages],
})
```

Veja [Erros localizados](/docs/signing/i18n) para o padrão de catálogos e overrides. Não armazene `label` no estado da fila; armazene o erro bruto e renderize a cópia localizada na fronteira do componente.

## URLs de objeto PDF

```tsx title="signed-preview.tsx"
import { usePdfObjectUrl } from "@signature-kit/react/browser-pdf"

export function SignedPreview({ bytes }: { bytes: Uint8Array | null }) {
  const url = usePdfObjectUrl(bytes)
  return url ? <a href={url} download="signed.pdf">Baixar PDF assinado</a> : null
}
```

O hook cria e revoga object URLs com um efeito mínimo de cleanup porque o recurso do navegador exige cleanup.
