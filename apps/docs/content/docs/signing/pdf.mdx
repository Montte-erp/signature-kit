**What you'll do:** sign PDF bytes in PAdES with `signPdf`, choose the `"pades-ades"` or `"pades-icp-brasil"` (AD-RB) policy, add optional visible stamps, and verify the result with `verifyPdf`.

The `Signatures` seam, provided by `a1SignaturesLayer`, does the signing; the PDF module only mutates the document.

## Install the package

The PDF module is `@signature-kit/pdf`. It consumes the same provider layer as the XML module.

```package-install
@signature-kit/pdf
```

<Callout type="info">
  `signPdf` requires the `Signatures` service in the requirements channel; `verifyPdf` does not.
</Callout>

## Sign a PDF

`signPdf(input: PdfSigningRequest)` returns an `Effect<Uint8Array, PdfError | CmsError | SignatureKitError, Signatures>` — the bytes of the signed PDF. Provide `Signatures` with `Effect.provide(a1SignaturesLayer(...))`.

```ts title="sign-pdf.ts"
import { signPdf } from "@signature-kit/pdf/sign"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { Effect, Redacted } from "effect"

const signedPdf = await Effect.runPromise(
  signPdf({
    pdf,
    name: "Maria Souza",
    reason: "Signed for approval",
    location: "São Paulo, BR",
    policy: "pades-icp-brasil",
    signatureLength: 32768,
  }).pipe(
    Effect.provide(
      a1SignaturesLayer({
        pfx,
        password: Redacted.make(password),
      }),
    ),
  ),
)
```

`signatureLength` reserves the `/Contents` placeholder. If the CMS signature is larger than the placeholder, signing fails with `pdf.SIGNATURE_TOO_LARGE`; increase the placeholder and sign again.

## ICP-Brasil AD-RB policy

`policy: "pades-icp-brasil"` uses the pinned PA_PAdES_AD_RB_v1_1 policy metadata from `@signature-kit/cms/icp-brasil`. You can override policy metadata only when you own the policy facts.

```ts title="explicit-policy.ts"
const signedPdf = signPdf({
  pdf,
  policy: {
    oid: "2.16.76.1.7.1.11.1.1",
    hashBase64: policyHashBase64,
    hashAlgorithm: "sha256",
  },
})
```

<Callout type="warn" title="AD-RB forbids CMS signingTime">
  With `policy: "pades-icp-brasil"`, the CMS `signingTime` signed attribute is prohibited. SignatureKit keeps it out of CMS for AD-RB; an optional `timestamp` only feeds the PDF signature dictionary `M`. The official ITI validator rejects CMS signatures that carry `signingTime` under this policy.
</Callout>

## Visible stamps

Visible stamps are drawn before the cryptographic signature is embedded, so the stamped page bytes are covered by the signature. Pass `stamp` to `signPdf` for one full visible block, and `rubric` when you need initials/rubrics on other pages.

```ts title="visible-stamp.ts"
const signedPdf = signPdf({
  pdf,
  policy: "pades-icp-brasil",
  stamp: {
    pageIndex: 0,
    rect: [72, 72, 260, 124],
    badge: {
      header: { text: "DIGITALLY SIGNED" },
      rows: [
        [{ label: "Signer", value: "Maria Souza" }],
        [{ label: "CPF", value: "***.123.456-**" }],
      ],
      footer: [
        { text: "ICP-Brasil" },
        { text: "Validate at ITI", link: "https://validar.iti.gov.br/" },
      ],
      qr: { text: "https://validar.iti.gov.br/" },
      theme: {
        borderColor: "#1D4ED8",
        backgroundColor: "#FFFFFF",
        headerBackgroundColor: "#DBEAFE",
        qrColor: "#1E3A8A",
      },
    },
  },
})
```

The `badge` schema supports:

- `header.text` for the top label;
- `rows` as one or more rows of `{ label?, value }` cells;
- `footer` segments with optional `link`; links become PDF annotations;
- `qr.text` for a generated QR code rendered into the badge;
- `theme` hex colors for border, background, header, text, separator, QR, and footer accents.

Use `inkPng` when you already have a handwritten signature image. Use `lines` for plain text, or `badge` for the structured government-style stamp. A visible stamp requires exactly one of `lines`, `badge`, `inkPng`, or `qr`.

```ts title="ink-and-rubric.ts"
const signedPdf = signPdf({
  pdf,
  stamp: {
    pageIndex: 0,
    rect: [72, 72, 220, 118],
    inkPng: signatureImagePng,
  },
  rubric: {
    rect: [500, 36, 560, 72],
    pages: "all-except-signature",
    initials: "MS",
    initialsTheme: {
      inkColor: "#111827",
      bracketColor: "#2563EB",
      backgroundColor: "#EFF6FF",
    },
  },
})
```

`pages: "all-except-signature"` is the safe rubric default: the main signature page gets the full visible block; the other pages get initials. Single-page documents skip the rubric pass.

For anchor-based placement — finding text such as "Assinatura" and turning it into a rectangle — use the [anchor placement recipe](/docs/recipes/anchor-placement).

## Verify a PDF

`verifyPdf` checks the PDF ByteRange, CMS signature, and coverage. It returns a value, so invalid signatures are represented as `valid: false`.

```ts title="verify-pdf.ts"
import { verifyPdf } from "@signature-kit/pdf/verify"

const report = await Effect.runPromise(verifyPdf({ pdf: signedPdf }))

report.valid
report.signatures.length
```

If you also need AD-RB profile validation, run `validatePdfConformance` from `@signature-kit/iti/conformance` after signing.
