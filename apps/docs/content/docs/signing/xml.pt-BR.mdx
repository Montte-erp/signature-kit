---

**O que você vai fazer:** assinar uma string XML com `signXml` na camada do `Signatures`, depois validar com `verifyXml` — que não exige signatário e roda em qualquer lugar.

## Instale o pacote

O formato XML vive em `@signature-kit/xml` e consome o serviço `Signatures` fornecido por um signatário.

```package-install
@signature-kit/xml
```

## Assine um documento XML

`signXml` recebe um `XmlSigningRequest` e retorna `Effect<string, XmlError | SignatureKitError, Signatures | XmlRuntime>` — o XML assinado como string. Satisfaça o requisito `Signatures` com `Effect.provide(a1SignaturesLayer(...))`: o A1 fornece o poder de assinatura, o módulo de formato só altera o documento.

```ts title="sign-xml.ts"
import { signXml } from "@signature-kit/xml/sign"
import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { Effect, Redacted } from "effect"

const signedXml = await Effect.runPromise(
  signXml({
    xml,
    referenceId: "nfe-1",
  }).pipe(
    Effect.provide(a1SignaturesLayer({ pfx, password: Redacted.make(password) })),
    Effect.provide(xmlRuntimeLayer),
  ),
)
```

## Verifique XML

`verifyXml` valida a estrutura e a criptografia da assinatura. Ele não precisa da layer do signatário porque a chave pública está em `KeyInfo`.

```ts title="verify-xml.ts"
import { verifyXml } from "@signature-kit/xml/verify"
import { Effect } from "effect"

const result = await Effect.runPromise(
  verifyXml({
    xml: signedXml,
    requireReferenceUri: "#nfe-1",
  }),
)

result.valid
result.signatureCount
```

<Callout type="info">
  Uma assinatura inválida, ou um `requireReferenceUri` que não está entre as referências assinadas, **não** é um erro do Effect — `verifyXml` ainda é bem-sucedido e retorna `result.valid === false`. `verifyXml` só falha no canal de erro nos casos abaixo.
</Callout>
