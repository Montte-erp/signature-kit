**What you'll do:** sign an XML string with `signXml` over the `Signatures` boundary, then validate with `verifyXml` — which needs no signer and runs anywhere.

## Install the package

The XML format lives in `@signature-kit/xml` and consumes the `Signatures` service provided by a signer.

```package-install
@signature-kit/xml
```

## Sign an XML document

`signXml` takes an `XmlSigningRequest` and returns `Effect<string, XmlError | SignatureKitError, Signatures | XmlRuntime>` — the signed XML as a string. Satisfy the `Signatures` requirement with `Effect.provide(a1SignaturesLayer(...))`: A1 provides the signing power, the format module only mutates the document.

```ts title="sign-xml.ts"
import { signXml } from "@signature-kit/xml/sign"
import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { Effect, Redacted } from "effect"

const signedXml = await Effect.runPromise(
  signXml({
    xml,
    referenceId: "nfe-1",
  }).pipe(
    Effect.provide(a1SignaturesLayer({ pfx, password: Redacted.make(password) })),
    Effect.provide(xmlRuntimeLayer),
  ),
)
```

## Verify XML

`verifyXml` validates the signature structure and cryptography. It does not need the signer layer because the public key is inside `KeyInfo`.

```ts title="verify-xml.ts"
import { verifyXml } from "@signature-kit/xml/verify"
import { Effect } from "effect"

const result = await Effect.runPromise(
  verifyXml({
    xml: signedXml,
    requireReferenceUri: "#nfe-1",
  }),
)

result.valid
result.signatureCount
```

<Callout type="info">
  An invalid signature, or a `requireReferenceUri` that is not among the signed references, is **not** an Effect error — `verifyXml` still succeeds and returns `result.valid === false`. `verifyXml` only fails on the error channel for the cases below.
</Callout>
