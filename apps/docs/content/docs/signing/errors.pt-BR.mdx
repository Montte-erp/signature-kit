**O que você vai fazer:** tratar `SignatureKitError` no canal de erro do Effect, entender seus campos estáveis e criar links diretos para o código exato que falhou.

<Callout type="info" title="Canal de erro tipado">
  As falhas não são lançadas com `throw`: elas vivem no canal de erros do Effect como um `SignatureKitError` com um `code` literal. O compilador obriga você a tratá-las — ou deixá-las se propagar, tipadas — em vez de descobri-las em tempo de execução.
</Callout>

## O formato do erro

`SignatureKitError` é uma classe com `_tag` fixo igual a `"SignatureKitError"`. Seus campos:

- `code` — um dos códigos literais `signature-kit.*` do catálogo abaixo.
- `retryable` — um boolean decidido **no ponto de falha**, não fixo por código.
- `reason` — texto diagnóstico humano quando é seguro e útil.
- `operation`, `provider`, `schemaName`, `issueMessage`, `status`, `url` — metadados estruturados de origem quando a fonte possui contrato real.

```ts title="tratar-erro.ts"
import { Effect } from "effect"

program.pipe(
  Effect.catchTag("SignatureKitError", (error) => {
    switch (error.code) {
      case "signature-kit.INVALID_INPUT":
      case "signature-kit.RESPONSE_SHAPE":
      case "signature-kit.UNSUPPORTED_OPERATION":
        return Effect.fail(error.message)
      default:
        return Effect.fail(error.message)
    }
  }),
)
```

Formatos e signers são pacotes separados — instale apenas o que cada caminho usa.

```package-install
@signature-kit/xml @signature-kit/pdf @signature-kit/http @signature-kit/clicksign
```
